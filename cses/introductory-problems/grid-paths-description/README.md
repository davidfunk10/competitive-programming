## Grid Paths Description (CSES Intro)

This was one of the hardest problems I have solved so far, but I truly think it improved my recursive skills. For this question, I intialized a 2x2 array called `onpath` that keeps track of which squares are in the current path and which arent. I initilized it to be 9x9 instead of 7x7 so I could create a border around the actual 7x7 array to avoid annoying out of bounds errors. Inside my `trypath` function, I looked for all possible paths that start from the top left square, end at the bottom left square, do not intersect with each other, and visit all 48 squares. I used depth-first-search to find them, and I prunned unnecessary cases if a path's prefix denoted a grid split or a dead end. This cut down time complexity enough to run just under the 1 second time constraint. This was one of the first problems I've done where time constraints actually matter and make you think deeper.
